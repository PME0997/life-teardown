# 方法论库（困难拆解工具箱）

## 选路表（先看这里）

| 问题结构 | 信号 | 选用框架 |
|---|---|---|
| 单链条因果 | "为什么会这样"且原因链单一 | 5 Whys |
| 多因素并发 | 人/方法/环境/工具/信息多线交织 | 鱼骨图 |
| 表达呈现混乱 | PPT/汇报/写作没条理、抓不住重点 | 金字塔原理 + SCQA |
| 问题大而模糊 | "就是感觉做不好"说不出哪 | MECE + Issue Tree |
| 多个解释并存 | 几种归因都有可能 | 奥卡姆剃刀 |
| 要落地改进 | 已知原因，求下次怎么做 | Inversion + 复盘四步法 |
| 环节过多抓不住关键 | 改进点太多 | 帕累托 80/20 |
| 要不要做某事 | 决策类 | Issue Tree + Inversion |

默认轻量：一次只用 1 个框架，上限 2 个（第 3 个需用户显式要求）。用户说"深挖"再叠加。

## 选路互斥说明（防止工具堆砌）

- **鱼骨图 vs MECE**：因素已知、只需归类排查 → 鱼骨图；问题本身模糊、需先拆成子问题 → MECE + Issue Tree。两者不并用（一个是归类已知因素，一个是拆分未知问题）。
- **奥卡姆剃刀**：不是独立框架，是"多假设产生后"的筛选步骤，跟在鱼骨图/5 Whys 之后用，不单独占一个框架名额。
- **Issue Tree vs MECE**：MECE 是拆分原则（互斥穷尽），Issue Tree 是其呈现形式（树状），两者同用算一个框架。
- **Inversion vs 复盘四步法**：求改进方案时两者常配合（Inversion 列必败路径，复盘四步法收口行动），算一个组合框架。
- **输出时必须说明**："本次用了 X 框架，为什么用它而不用 Y"——强迫自检工具选择，这是反谄媚的一种（防止"看起来专业"的堆砌）。

## 一、5 Whys（丰田根因法）

对答案连续追问"为什么"，一般 4-6 层到底。
- 适用：原因链单一线性的问题。
- 纪律：每层答案必须有用户原话或事实支撑；禁止停在"我不够认真/能力不行"这类不可操作的层；挖到用户控制范围外的因素时，转为"在这个约束下我能改变什么"。
- **失效信号**：某一层的答案出现多个分支（→ 换鱼骨图），或挖到情绪/习惯层（→ 触发双线程评估），或连续两层答案重复（→ 已到根，停）。

## 二、鱼骨图（Ishikawa，多因素归因）

把问题作为鱼头，按类别铺开候选原因。个人场景推荐类别：**信息**（输入是否完整准确）、**方法**（会不会）、**执行**（做了没、做到位没）、**环境**（外部条件/他人）、**状态**（精力/情绪/时间）。
- 产出是假设清单，不是结论：每个候选原因标注支持它的证据，证据不足的排除。
- 配合奥卡姆剃刀：先验证最简单、证据最直接的解释。
- **失效信号**：类别铺开后仍找不到可验证的假设（→ 问题定义本身有误，回到事件还原），或因素间有强因果链而非并列（→ 换 5 Whys）。

## 三、金字塔原理（Minto，表达与结构化）

对症：汇报混乱、PPT 信息堆砌、抓不住重点、思路跳脱。
- 四原则：结论先行、以上统下、归类分组（MECE）、逻辑递进。
- SCQA 结构：情境(Situation)→冲突(Complication)→疑问(Question)→答案(Answer)，用于开场和叙事线。
- 用于 PPT 诊断时：先问"这页的一句话结论是什么"，答不上来就是结构问题；每页只承载一个论点，论据不超过 3 条。
- 自检：能用一句话说出中心思想；支撑论点相互独立且合起来穷尽；顺序符合时间/结构/重要性之一。
- **失效信号**：问题不在"表达呈现"而在"内容本身没想清楚"（→ 换 5 Whys / MECE 先解决内容），或用户主诉是理解/执行而非表达（→ 重新选路）。

## 四、MECE + Issue Tree（大问题分解）

把模糊的大问题拆成相互独立、完全穷尽的子问题，直到每个末端是可回答、可行动的小问题。
- 规则：同层分支互斥不重叠；合起来覆盖原问题；末端可执行。
- 决策类问题用法：第一层拆"留/走/折中"，第二层拆每个选项的"收益/代价/风险/可逆性"。
- **失效信号**：拆到第三层仍无法产生可验证的末端问题（→ 信息不足，先问诊补充），或分支无法做到互斥（→ 问题维度选错，重新选拆分维度）。

## 五、奥卡姆剃刀（解释选优）

多个解释并存时，优先验证假设最少、最简单的那个。
- 用法：列出全部候选解释 → 按所需假设数量排序 → 从最简单的开始找证据验证/排除。
- 防过度归因：避免把"忘带钥匙"解释成"潜意识自我破坏"这类复杂归因。
- **失效信号**：最简解释被证据明确排除（→ 依次验证下一个），或所有解释假设数相当（→ 剃刀失效，改用证据强度排序）。

## 六、Inversion（逆向思维，芒格）

不问"怎么成功"，先问"怎么一定会失败"，列失败模式清单，再逐条排除。
- 适用：改进方案设计、重大决策前的风险扫描。
- 步骤：列出"如果要搞砸这件事我会怎么做"→ 逐条检查当前是否会踩 → 转化为避免清单。
- **失效信号**：失败模式清单与当前情境无关（→ 问题还原不到位），或用户已在执行避免清单仍失败（→ 根因不在已识别的失败模式，回到根因确认）。

## 七、复盘四步法 + KISS

复盘四步法：回顾目标 → 评估结果（差距）→ 分析原因（成功/失败的关键因素）→ 总结规律（下次适用什么）。
KISS 收口：Keep（继续保持的）/ Improve（需要改进的）/ Stop（要停止的）/ Start（要开始做的）。每次复盘的行动清单按 KISS 归类。
- **失效信号**：目标本身模糊无法回顾（→ 先补事件还原的目标层），或原因分析停在不可操作层（→ 用 5 Whys 下钻后再收口）。

## 八、帕累托 80/20（优先级）

找造成 80% 困难的 20% 关键环节，优先投入。
- 用法：列出全部卡点/改进点 → 估算各自对结果的影响占比 → 只取前 1-2 个进入行动清单，其余记录但不行动（避免清单过长导致不执行）。
- **失效信号**：卡点影响占比接近均匀、无明显关键少数（→ 80/20 失效，改为按"可改变性"排序，先攻最容易动的）。
